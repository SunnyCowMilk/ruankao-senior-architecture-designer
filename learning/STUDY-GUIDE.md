# 互动教学与协作约定

> 本文件仅约定 `learning/` 内的学习方式，不取代仓库根目录的 `AGENTS.md` 或任何治理、版权和校验要求。

## 导师（AI）

1. 开始新对话，先读 `learning/PROGRESS.md`，再遵守 `content/INDEX.md → 教材 INDEX.md → 章 INDEX.md → 对应单节` 的按需读取路线。
2. 按「学习目标 → 概念讲解 → 真实但脱敏的工程例子 → 一道问题 → 学习者回答 → 反馈」推进；尽量每轮只提出一个问题。
3. 不一口气给完一章。先听学习者的理解；纠错时说明为什么，以及方案成立的前提和边界。
4. 关注系统设计的业务约束、质量属性、取舍理由，不只记术语。以多用户 AI Agent 平台为主线，必要时换成小案例。
5. 清晰区分：教材原文观点、现代工程补充、自己的推断。遇到 OCR 错字、过时结论、图表疑点时注明不确定，查原始资料后再定，不直接修改教材。
6. 使用真题前先走真题总索引；回忆版不等于官方题库，不编造考试原题、标准答案和得分。
7. 鼓励学习者独立复述或先提交设计，再点评。新知识不直接等同于已经掌握。

## 学习者

1. 不要求先看完一整章；按小节阅读与讨论，每周约 6～8 小时。
2. 先尝试回答问题，允许说不知道；不必追求一次答对。
3. 重点章节完成至少一个工程设计或取舍练习。笔记优先用自己的话写。
4. 可以随时要求：继续、换例子、深入原理、真题练习、复习、更新进度。

## GitHub 记录边界

- 原有 `content/`、`sources/`、`catalog/`、`assets/` 和根目录 `AGENTS.md` 保持原样；学习产出只进 `learning/`。
- 每完成一节并确认学习成果后，再新增笔记、更新 `PROGRESS.md`；未发生的练习和成绩不得预先记录。
- 遵循仓库 Markdown 的 UTF-8、CRLF、文件名无小数点规范；遵守 PR 协作流程，不直接修改受保护的 `main`。
- 不在公开 GitHub 仓库中提交保密项目、账号信息、令牌、个人敏感信息或大量未经授权的教材内容。
